维护项目宪法。本团队的宪法就是项目根的 `AGENTS.md`，**不另建** `constitution.md`。

先读 `spec-workflow` skill 的「项目宪法就是 AGENTS.md」一节，再读 `AGENTS.md` 全文。

用户诉求：$ARGUMENTS

## 有诉求时

1. 判断这条约束属于 `AGENTS.md` 的哪个章节（语言沟通 / Git / 需求拆解 / Skill 使用 /
   编码原则 / 自动化验证 / 高风险操作 / 工程上下文）。若都不属于，才新增章节。
2. 检查是否与既有条目冲突或重复。冲突要指出并让用户决断，重复就改既有条目而不是追加。
3. 约束必须**可判定**。「代码要优雅」不是约束，「组件默认导出，文件名与组件名一致」才是。
4. 写清**为什么**。没有理由的约束会在第一次不方便时被绕过。
5. 如果这条约束的细节超过三行，正文只留一句结论，细节写进对应 skill，正文指向它。

## 留空时（宪法体检）

逐条核对 `AGENTS.md` 与仓库现状是否还对得上，输出问题清单，不擅自修改：

- 提到的命令是否都还存在（对照根 `package.json` 的 scripts）
- 提到的 skill / agent 文件是否都还在
- 提到的目录结构是否与实际一致
- 是否有仓库里已成事实、但宪法没写的约束
- 是否有写了但实际从未执行的约束（这类要么删，要么补执行手段）

## 结束时

汇报：改了哪几条、为什么、是否需要同步改某个 skill。不执行任何 Git 操作。
